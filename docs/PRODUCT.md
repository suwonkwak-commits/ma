# 무림여록 — 첫 출시를 향한 제품 계획

## 목표와 현재 범위

Android Google Play와 iOS App Store에 출시할 수 있는 한국어 무협 방치형 RPG를 만든다. 수익 목표는 반복 플레이의 재미와 유저 유지가 확인된 이후 검증한다. 지속 수익이나 매출은 보장할 수 없으며, 초기 버전은 게임성을 확인하기 위한 로컬 플레이 프로토타입이다.

첫 버전의 중심은 **수련 → 경지 돌파 → 무공 강화 → 강호 탐험과 자동 전투 → 보상 → 다음 경지**다. 이미지와 이펙트 이전에 정보 위계, 조작 피드백, 성장 속도, 저장 안정성을 갖춘다.

## 첫 버전에서 확인할 경험

- 처음 들어온 사람이 로그인 없이 수련을 시작하고 다음 목표를 이해한다.
- 직접 수련과 시간 경과로 내공을 모으고, 경지 돌파로 새 탐험지를 연다.
- 무공의 설명과 능력치를 비교하고 강화하거나 장착한다.
- 탐험 중 자동 전투의 결과와 보상을 전투 기록에서 확인한다.
- 앱을 다시 열면 로컬 진행을 복원하고 최대 8시간 범위의 방치 보상을 확인한다.
- 세로형 모바일 화면을 기본으로 삼되 웹에서도 같은 흐름을 검증한다.

첫 버전에는 서버 계정, 클라우드 동기화, 실제 결제, 광고, 길드, PvP, 경쟁 순위가 없다. 현재 기기 저장은 출시용 계정 복구와 부정행위 방지를 대신하지 않는다.

## 세계관과 콘텐츠 원칙

무림·내공·경지·문파·강호 같은 장르의 널리 쓰이는 개념을 출발점으로 삼는다. 특정 작품의 인물·서사·고유 무공·삽화를 옮기지 않는다. 무공 이름, 지역, 짧은 서술은 이 게임을 위해 새로 구성한다. 제공된 링크의 접근 결과와 실제 참고 범위는 [REFERENCES.md](./REFERENCES.md)에 기록한다.

첫 콘텐츠는 설명 가능한 소수의 무공, 점진적으로 열리는 탐험지, 분명한 경지 단계로 제한한다. 콘텐츠 수를 늘리기 전에 처음 10분의 목표, 패배 이유, 다음 성장 행동을 플레이어가 이해하는지 확인한다.

## 수익화 검증 순서

1. **재미와 유지:** 튜토리얼 완료, 첫 돌파, 첫 전투 승리, 다음날 재방문, 저장 복원 성공을 측정한다. 초반에는 개인정보 없는 수동 플레이 테스트로 시작한다.
2. **선택형 가치:** 외형·칭호·화면 테마 등 구매 가치를 검토한다. 핵심 진행에 필요한 구매를 먼저 강제하지 않는다.
3. **선택형 보상 광고:** 플레이어가 명시적으로 선택하는 광고를 실험한다. 보상, 제한 횟수, 실패 시 동작을 명확하게 표시한다. 기본 수련·탐험은 광고 없이 플레이할 수 있어야 한다.
4. **광고 제거 또는 편의 상품:** 광고 배치가 확정된 뒤 실제 효용을 제공하는 상품만 설계한다. 복원 가능한 구매와 각 스토어의 결제 정책을 함께 구현한다.

지표는 D1/D7 유지율, 세션 길이, 첫 돌파까지 시간, 패배 후 이탈률, 광고 선택률, 구매 전환율, 환불률을 함께 본다. 광고 노출량이나 단기 매출만으로 품질을 판단하지 않는다. 확률형 유료 상품은 첫 출시 범위에 넣지 않는다.

## 단계별 완료 기준

| 단계 | 산출물과 완료 기준 |
| --- | --- |
| 플레이 가능한 기초 | 수련·돌파·강화·탐험·저장·방치 보상을 직접 조작하고 핵심 로직 테스트가 통과한다. |
| 모바일 알파 | Android와 iPhone 실기기에서 세로 화면, 터치 영역, 배경 전환, 재실행, 장시간 방치, 오프라인 동작을 확인한다. |
| 콘텐츠와 밸런스 | 첫 30분 콘텐츠와 다음날 돌아올 목표를 구성하고, 테스트 유저의 이탈 지점을 수정한다. |
| 출시 기반 | 앱 식별자·아이콘·서명·개인정보 처리방침·지원 연락처·연령 등급·스토어 설명과 스크린샷을 준비한다. 실제 SDK를 기준으로 데이터 수집 및 광고·추적 동의를 확인한다. |
| 수익화 베타 | 스토어 샌드박스 결제·구매 복원·광고 실패·보상 중복 방지를 검증하고 TestFlight 및 Play 내부 테스트로 배포한다. |
| 스토어 제출 | 크래시·저장 손실·결제 오류를 해결한 서명 빌드를 제출한다. 심사 승인과 공개 출시는 별도 완료 단계다. |

## 출시 전 기술 과제

- 실기기와 각 플랫폼의 백그라운드·재실행 수명주기 검증
- 기기 시간 변경, 저장 손상, 마이그레이션과 복구 정책 결정
- 계정 복구나 경쟁 기능이 필요해질 경우 서버가 보상·결제를 검증하도록 설계
- 수익화 SDK 도입 후 개인정보 표시, 데이터 보관, 동의 및 정책 재검토
- 텍스트 가독성, 큰 글자, 색상 대비, 스크린리더, 작은 화면 확인
- Android 릴리스 빌드와 iOS 서명 빌드의 실제 설치·테스트

개발 환경에서 웹이 실행되거나 테스트가 통과하는 것만으로 스토어 제출 준비가 끝났다고 판단하지 않는다.
